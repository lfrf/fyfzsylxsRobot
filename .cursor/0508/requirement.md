# 0508 Requirement

## 1. 项目目标
构建一个以唤醒词为入口、以三态状态机为主线的机器人交互系统。系统启动后先进入待机，仅监听唤醒词；唤醒后进入准备状态；准备完成后进入工作状态，所有对话交互都在工作状态内部持续循环。

---

## 2. 核心状态定义

### 2.1 `STANDBY`
- 启动后的默认状态
- 仅监听唤醒词
- 不启动视觉模块
- 不启动人脸追踪
- 不上传视频帧

### 2.2 `PREPARING`
- 唤醒词触发后进入的中间状态
- 负责启动视觉模块、人脸追踪和远程视频上传
- 负责触发远程人脸识别链路
- **不处理语音输入**
- **不等待用户回答**
- 准备完成后应立即切换到 `WORKING.LISTENING`

### 2.3 `WORKING`
- 正常交互状态
- 工作状态内部包含：`LISTENING -> RECORDING -> UPLOADING -> THINKING -> SPEAKING -> LISTENING`
- 语音输入只在该状态内部处理
- `SPEAKING` 结束后回到 `LISTENING`
- `LISTENING` 10 秒无输入时，退出 `WORKING` 回到 `STANDBY`

---

## 3. 用户体验目标
1. 用户说唤醒词后，系统快速进入可交互准备阶段
2. 系统在准备阶段内启动视觉和远程识别
3. 用户第一次说话后进入持续工作交互
4. 工作状态下每一轮结束都回到工作态监听输入，而不是回到准备状态
5. 工作态长时间无输入时自动回待机

---

## 4. 关键约束
- 待机阶段不得启动视觉模块
- `PREPARING` 不得承担语音输入识别逻辑
- 工作状态内的输入监听与超时判断必须独立于准备阶段
- 视觉启动与停止必须和状态切换绑定
- 状态日志必须区分 `STANDBY`、`PREPARING`、`WORKING` 三段

---

## 5. 后续扩展预留
- 远程人脸识别结果可用于欢迎语和用户名注册引导
- 用户名注册不属于 `PREPARING` 的等待职责，应挂接在工作态交互流程中
- 长对话 memory 和 LLM 注入作为下一阶段扩展点，暂不纳入本轮实现范围
